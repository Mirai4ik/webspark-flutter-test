# Webspark Shortest Path

Flutter-застосунок для отримання завдань з API, пошуку найкоротших шляхів, перевірки результатів на сервері та перегляду маршрутів на сітці.

## Запуск

Перевірено з Flutter 3.41.8 / Dart 3.11.5. Android SDK потрібен для Android-збірки, macOS та Xcode - для iOS.

```sh
flutter pub get
flutter run
```

URL за замовчуванням: `https://flutter.webspark.dev/flutter/api`.

1. Введіть URL і натисніть **Start**.
2. Дочекайтеся завершення обчислень та натисніть **Send results to server**.
3. Після підтвердження сервера відкриється список результатів.
4. Натисніть на результат, щоб переглянути маршрут на сітці.

## Реалізовані вимоги

| Пункт | Реалізація |
| --- | --- |
| 1.1 | Перевірка HTTP/HTTPS URL, підтримка GET-параметрів, локальне збереження та відновлення адреси через SharedPreferences. |
| 1.2 | Окремий екран обчислень, GET за збереженим URL, фактичний прогрес виконання, обчислення у фоновому isolate, POST усіх результатів одним запитом. Кнопка надсилання має loader і блокується на час запиту. Помилки відображаються з можливістю повторної спроби. |
| 1.3 | Список усіх підтверджених результатів у форматі `(2.1) -> (1.2) -> (0.2)` з переходом до окремого результату. |
| 1.4 | Маршрут текстом і на сітці, координати у кожній клітинці, усі кольори з умови. Великі сітки можна прокручувати. |
| 2 | Власний алгоритм BFS з ООП, перевіркою вхідних даних та відновленням найкоротшого маршруту; готові бібліотеки пошуку шляху не використовуються. |

Кольори: початок `#64FFDA`, кінець `#009688`, перешкода `#000000`, шлях `#4CAF50`, вільна клітинка `#FFFFFF`.

## Алгоритм і контракт API

Координата `x` означає стовпчик, `y` - рядок; початок координат у верхньому лівому куті. Пошук у ширину перевіряє вісім сусідніх клітинок. Маршрут містить початок, кінець і кожну проміжну клітинку, зокрема на прямій або діагоналі. Часова та просторова складність - O(N²) для сітки N × N, де 2 ≤ N ≤ 99.

Це усуває причину `Result incorrect`: попередній алгоритм міг пропускати клітинки на прямому відрізку. Сервер відхилив `(0,3)->(1,2)->(3,0)` та прийняв `(0,3)->(1,2)->(2,1)->(3,0)`.

Формат відображення в інтерфейсі та формат POST розділені. Сервер отримує рядкові координати та шлях з комами, без пробілів:

```json
[
  {
    "id": "task-id",
    "result": {
      "steps": [{"x": "0", "y": "0"}, {"x": "1", "y": "1"}],
      "path": "(0,0)->(1,1)"
    }
  }
]
```

GET і POST використовують ту саму збережену адресу разом з GET-параметрами. Перехід до списку результатів відбувається лише після `correct: true` для кожного надісланого завдання. Порожня чи неповна відповідь сервера не вважається успіхом. Для мережевих запитів задані таймаути.

## Перевірка

```sh
flutter analyze
```

Окрема ручна перевірка живого API надсилає справжній GET і POST:

```sh
dart run tool/verify_api.dart
# Або з власним URL:
dart run tool/verify_api.dart 'https://example.com/api?key=value'
```

15 жовтня 2026 року сервер Webspark підтвердив обидва поточні завдання: HTTP 200, `error: false`, `correct: true` для кожного.

## Android APK

```sh
flutter build apk --release
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`. Release-збірка використовує стандартний debug-ключ Flutter для локального встановлення; для публікації в Google Play потрібен власний ключ підпису.

## Структура

- `lib/domain/` - координати, валідація завдання, BFS, результат і його формати.
- `lib/data/task_api.dart` - збереження URL, HTTP та перевірка відповідей сервера.
- `lib/presentation/` - введення URL, обчислення, список результатів та сітка.
- `tool/verify_api.dart` - перевірка обчислень на живому API.
